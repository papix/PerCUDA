# AGENTS.md

Setup, commands, layout and style are in `CONTRIBUTING.md`; read it first.

## Checks

- `prove -l t/` after every change; `author/lint.sh` (run `author/lint.sh --fix`
  to apply perltidy) and `minil test --release` before committing.
- GPU tests skip silently without CUDA::DriverAPI or a device. A pass on a
  machine without a GPU, including CI, only proves the perl engine. Check
  `perl -MCUDA::DriverAPI -e1` first when GPU work matters.

## Decisions and pitfalls

- The perl engine must give exactly the GPU's results in `perl_mode =>
  'compat'` (the maintainer's decision): single precision rounding after every
  operation, 32-bit integer wrap, inf/nan on division by zero, C-like
  conversions. Any change to `CodeGen::CUDA` needs the matching change in
  `CodeGen::Perl`; `t/04_semantics.t`, `t/05_mandelbrot.t` and
  `t/06_parity.t` compare the engines exactly.
- The GPU code is compiled with `--fmad=false`; fused multiply-add would break
  the exact match.
- The kernel ABI is defined once, in `PerCUDA::Analyzer::kernel_params`; the
  CUDA generator and the GPU engine both follow it.
- The last Perl axis is CUDA's x axis (coalesced access); launch dimensions
  in `Engine::GPU` are reversed accordingly.
- No experimental Perl features; stable `use v5.40` features only.
- `Build.PL`, `META.json`, `README.md` are generated by Minilla: edit
  `cpanfile`, `minil.toml` or the POD in `lib/PerCUDA.pm`, then `minil build`.
  Author-test config lives in `xt/` because Minilla does not copy dotfiles.
- CUDA::DriverAPI changes quickly in its own repository; check its POD before
  relying on an API. All runners share one CUDA context per device, so a
  sticky kernel error breaks every runner in the process.
- PDL is optional: never `use PDL` in `lib/`; detect ndarrays with
  `blessed && isa('PDL')` (`PerCUDA::Data::is_ndarray`). `t/09_without_pdl.t`
  hides PDL. Dimensions are outermost first everywhere in PerCUDA and
  CUDA::DriverAPI, the reverse of `$ndarray->dims`; never transpose, and never
  convert nested arrays to ndarrays internally (slower than `write_array`).
- The driver loads images lazily: a broken cache entry fails on the first
  `run`, where `Engine::GPU` recompiles and retries once.
